The production stack uses the image versions from [Supabase self-hosted/v0.8.1](https://github.com/supabase/supabase/tree/self-hosted/v0.8.1/docker). Kong is an officially supported alternative to the default Envoy gateway. The database initialization fragments and gateway routing here adapt that distribution; Supabase's source is licensed under Apache-2.0, reproduced in [LICENSE-SUPABASE](LICENSE-SUPABASE). Salebell modifications omit unused services and routes, retain only legacy JWT keys generated per installation, keep administration private, and delegate function authentication to the existing handlers. The runtime entrypoint admits only Salebell's own function names.

Supabase services are internal to Docker. Caddy publishes only HTTP/HTTPS for the web and API hostnames. Storage, Studio, metadata administration, the pooler and analytics are omitted because Salebell does not need them. Realtime is retained for the live event feed.

References: [Docker deployment](https://supabase.com/docs/guides/self-hosting/docker), [self-hosted functions](https://supabase.com/docs/guides/self-hosting/self-hosted-functions), [email templates](https://supabase.com/docs/guides/self-hosting/custom-email-templates), [HTTPS proxy](https://supabase.com/docs/guides/self-hosting/self-hosted-proxy-https).

`npm run self-host -- upgrade` backs up the current database and Vault key material, then uses the versions pinned in the checked-out source. Review changes and take an off-server backup before upgrading. A Postgres major upgrade requires an explicit database migration; changing the major image tag against an existing volume is unsupported. Keep `db-config` alongside the database: it contains persistent encryption material required to restore saved Apple keys. See `docs/SELF_HOSTING.md` for installation, backup and restoration.
